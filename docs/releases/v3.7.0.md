## 一、版本概览

本版本是 WorkBuddy Token 监测的首次公开发布，交付一个**本地优先、只读**的桌面 AI 应用用量监测工具。

工具读取 WorkBuddy、Qoder、Codex、Claude Code、CodeBuddy 等应用自身写下的用量记录，不修改被监测应用的任何文件、不注入界面、不代理网络流量，因此不会随上游版本更新而失效。呈现分三个形态：置顶精灵桌宠、浏览器仪表盘、本地 HTTP 接口。

本版本的核心工程结论有两条。第一，「每秒多少 token」在上游数据中没有现成字段，本工具提供了实时端到端、扣除工具时间的有效值、以及基于 trace 耗时的生成基线三套口径，并在界面上明确区分，避免把端到端吞吐误读为模型解码速度。第二，桌宠需要真透明窗口，tkinter 的色键透明会产生边缘彩边，因此改用分层窗口加预乘位图实现。

## 二、更新内容

### 2.1 数据采集与指标

- **上下文占用**：实时读取会话用量表中的已用与总量字段。
- **输入与输出 tokens**：解析用量记录的原始字段，按消息标识去重，避免重试导致的重复计数。
- **缓存命中、思考 tokens、积分**：分别对应缓存命中字段、思考 token 字段与积分字段。
- **下行与上行有效速率**：通过 callId 配对工具调用，从请求间隔中扣除工具执行时间，得到更接近模型真实吞吐的每秒 token 数。本机实测工具执行约占请求间隔的 61%，不扣除会显著低估速率。
- **端到端速率**：未扣除工具时间的原始口径，保留用于对照。
- **生成速率基线**：解析 trace 中 type 为 generation 的 span 耗时，按会话与结束时间与请求记录对齐，本机实测中位误差 17 毫秒、命中率 80.9%。
- **燃烧率**：tokens 除以活跃分钟数，活跃分钟按各会话首尾跨度求和。
- **环比**：今日对比昨日同时段、近 7 天对比前 7 天。
- **逐分钟吞吐**：提供 60 分钟粒度序列，供火花线与趋势图使用。
- **增量缓存**：以文件修改时间与大小构成指纹，首次解析约 3.0 秒，之后约 0.9 秒，缓存结构版本升至 v7，新增首字延迟、精确耗时与数据来源标记字段。

### 2.2 桌宠形态（v3 主要变化）

- **精灵动画**：精灵表为 1536×2288 RGBA，8 列 11 行、单格 192×208，含 9 个动作与 16 方向注视，按 manifest 逐帧、按帧时长驱动。
- **状态机与 token 流联动**：会话工作中映射 running，会话活跃但暂无请求映射 waiting，单轮完成 6 秒内映射 review，上下文达到 95% 映射 failed 并同时弹气泡与提示音，空闲映射 idle，鼠标在 520 像素内按角度注视。
- **点击与拖动**：单击挥手、双击跳跃、拖动记忆位置，以 4 像素阈值区分点击与拖动。
- **悬停展开与单击钉住**：折叠态为 30×30 头像加活动状态点，悬停临时展开 268 像素宽的逐行面板，移开自动收起，单击钉住。
- **宠物尺寸**：50 / 75 / 100 / 125 / 150% 五档，切换时重建精灵并按新尺寸重绘。
- **随机漫步**：默认 15 秒间隔、每步 8 像素、90 毫秒帧进，可在菜单关闭。
- **气泡提示**：圆角、色键透明、自动消失、不抢焦点。
- **自绘右键菜单**：Canvas 绘制圆角面板，含速率口径、宠物大小、漫步、注视、提示音、系统与导出入口。
- **真透明分层窗口**：改用分层窗口更新加快预乘 BGRA 位图，边缘无彩边，透明像素天然点击穿透。
- **贴靠被监测应用窗口**：按进程名定位窗口并按 DPI 换算坐标，一键贴靠到模型选择器旁。

### 2.3 仪表盘

- 暗色速率状态条、环比 KPI、堆叠趋势、生成速率基线与会话明细。
- 「正在运行」卡片展示并行会话。
- 「模型占比」每行内嵌 12 小时迷你柱，柱高为输出 tokens 除以 3600 得到的平均速率。
- 仪表盘为单文件、手写 SVG、无外部依赖，可离线打开，也可通过快照脚本导出为静态页。

### 2.4 告警与提示

- 上下文占用达 80% 触发警告，达 95% 触发严重告警，均联动气泡、提示音与 failed 动画。
- 积分阈值提醒默认关闭（阈值为 0），需要时按额度填写。
- 提示音可在菜单关闭。

### 2.5 多应用与多服务商

- 数据源覆盖 WorkBuddy、Qoder、Codex、Claude Code、CodeBuddy。
- 余额查询内置 9 个服务商模板，并支持为每个服务商配置 Python 提取器，linoroute、LMU、智谱已内置。
- 导出 CSV 支持按范围导出当日用量，提供导出端点与菜单入口。

### 2.6 启动与系统集成

- `app.pyw` 作为启动器，由图形化解释器运行，全程无控制台窗口；探测服务端口与桌宠单实例锁，缺哪个补哪个，再打开仪表盘，全部操作幂等。
- `start.cmd`、`stop.cmd`、`stop.ps1` 提供一键启停，停止时按命令行精确匹配本目录进程，不影响其它 Python 进程。
- 全屏自动隐藏：前台应用全屏时自动隐藏桌宠，2.5 秒轮询判定。
- 开机自启：写入当前用户启动项，勾选即生效。
- 单实例保护：桌宠占用固定本地端口作为互斥锁，重复启动直接退出。

## 三、修复项

### 3.1 窗口过程内回调 Tk 导致解释器崩溃（严重）

在窗口过程里通过延迟回调机制调用 Tk，会与 Tk 自身消息泵发生重入，触发 `Fatal Python error: PyEval_RestoreThread`，进程直接退出且无提示。已改为窗口过程只做入队，输入统一由主线程每 80 毫秒消费一次，彻底消除重入路径。

### 3.2 高 DPI 下胶囊位置偏移

显示器缩放不为 100% 时，直接使用物理坐标会导致贴靠位置偏移。已引入系统 DPI 换算，并按换算后坐标重算贴靠位置。

### 3.3 上下文占用字段缺失导致的空值与除零

当数据源未提供上下文占用比例时，空值与空列表在聚合中可能引发除零或异常。已统一返回 0 作为安全值。本机 Qoder 样本中该字段命中 0 次，因此该数据源当前显示为「—」，此修复属于字段出现后的正确性保障。

### 3.4 缓存指纹失效导致重复全量解析

原按文件路径与时间判断缓存新鲜度，改动频繁时命中率低。已改为修改时间加大小的组合指纹，解析时间从 3.0 秒降至 0.9 秒。

### 3.5 缺少 tkinter 时无法启动

托管 Python 发行版不含 tkinter，直接启动会报模块缺失。现在检测到该情况会自动切换到系统 Python 重启自身。

## 六、安装与升级

1. 确保系统已安装 Python 3，并包含 tkinter 与 Pillow。Windows 官方安装包默认包含两者。
2. 解压发布包到任意目录，建议路径不含空格与中文，避免命令行脚本解析异常。
3. 双击 `start.cmd` 启动服务与桌宠，仪表盘默认在浏览器打开。
4. 首次运行会在同目录生成位置与偏好文件、缓存目录，均已在 `.gitignore` 中排除。
5. 停止使用双击 `stop.cmd`，或右键桌宠选择退出。

本版本为首次公开发布，无升级迁移步骤。后续 PATCH 版本可直接覆盖文件，缓存会自动按版本号重建。

## 七、已知问题

1. **仅 Windows 可用**：桌宠依赖分层窗口、DPI 查询、窗口过程钩子、启动项写入等 Windows 接口，未提供 macOS 与 Linux 实现。仪表盘与服务在其它平台理论可运行，但未经测试。
2. **依赖系统 Python 的图形组件**：托管 Python 缺少 tkinter 时需自动切换系统 Python。若目标机器未安装带 tkinter 的 Python 3，桌宠无法启动，此时仅仪表盘可用。
3. **生成基线数据滞后**：被监测应用的 trace 文件在会话或工作流结束后才落盘，因此基线为历史参考值而非实时读数。新会话需等待结束或重启应用后才有基线数据。
4. **部分数据源上下文占用显示为空**：Qoder 记录未携带上下文占用比例字段，该源当前显示「—」。这是数据源限制，非计算错误。
5. **三项系统集成功能待完整验证**：系统托盘、全局热键（默认组合键）、开机自启已实现，但状态为待验证，在部分系统策略或安全软件拦截下可能不生效。
6. **不提供快捷方式文件**：当前构建环境禁止脚本实例化系统托盘与快捷方式所需的组件，改用纯二进制方式写 Shell Link 后系统判定为无效，因此发布物不含快捷方式文件，需按 README 用系统「发送到」自行创建。
7. **速率口径为端到端吞吐**：请求间隔包含模型排队与工具执行时间，因此实时速率天然低于纯解码速度。需要真实解码速度请参考生成基线口径。
8. **单实例锁依赖固定端口**：桌宠以固定本地端口作为互斥锁，若该端口被其它程序占用，可能影响重复启动判定。
9. **资产许可与代码许可不一致**：代码为 MIT，`assets/` 下精灵素材为 CC BY-NC-SA 4.0，仅限非商业用途且必须署名并以相同方式共享。商业使用需自行替换素材。
10. **第三方商标资源**：`assets/logos/` 为各服务商商标，仅用于识别所监测的服务，商标权归各自权利人，不随本项目许可授权。
